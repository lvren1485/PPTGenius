## 三、本阶段成员进展与工时

### 1. 潘越

- 组织端到端联调，将“大纲生成 -> RAG 检索 -> 内容增强 -> PPT 导出”串联为可演示流程。
- 将评估指标拆为结构性指标、检索指标、内容指标和工程指标，形成第三次周报中的量化口径。
- 整理 benchmark 样例需求，要求覆盖商业、教学、学术三个场景。
- 记录当前风险与原因：评测样本仍偏少、用户测试尚未启动、demo 部署未完成。
- **本阶段工时：18 小时**。

### 2. 罗力

- 基于集成反馈优化 Prompt，增加模板类型（通用/商业/学术/教学）与风格参数（正式/精简/详细）。
- 在 pipeline 中加入用户额外要求参数，支持根据“成本、进度、风险”等约束调整输出。
- 优化内容融合策略，要求生成内容优先使用检索片段，不足时降低语气强度，减少编造数字。
- 配合 benchmark 指标，明确页数准确率和关键词覆盖率的计算方式。
- **本阶段工时：16 小时**。

### 3. 左凌旭

- 调整 RAG 检索接口，增加 `retrieve_with_scores`，让检索结果可输出来源与分数，便于后续过滤低分片段。
- 将增强后的来源写回 `rag_sources` 与备注区，使“PPT 中知识的可溯源率”可被脚本统计。
- 设计并实现 3 条 benchmark 样例，覆盖 RAG 教学、医学影像 AI、商业汇报叙事结构。
- 运行当前 benchmark，得到预期来源召回率、可溯源页比例等初始指标。
- **本阶段工时：18 小时**。

### 4. 上官思洋

- 扩展 Web demo 表单，增加 PPT 模板选择、内容风格选择和内容调整要求输入。
- 增加浏览器本地历史任务记录，支持恢复上次主题、模板、页数和调整要求，用于多轮迭代。
- 保持上传资料、生成下载和备用下载链接流程可用，并完成前端生产构建验证。
- 整理 demo 部署待办：后端同源部署、CORS 配置、环境变量与启动脚本固化。
- **本阶段工时：18 小时**。
