# PPT-Genius 项目双周报

**汇报周期**：2026-04-13 至 2026-04-26

**提交日期**：2026-04-26

**项目名称**：PPT-Genius（基于 LLM 与 RAG 的 PPT 大纲智能生成与内容深度补全系统）

## 一、组内分工

| 成员     | 角色 | 主要分工                                         |
| -------- | ---- | ------------------------------------------------ |
| 潘越     | 组长 | 项目统筹、系统集成与接口设计、集成测试与进度协调 |
| 罗力     | 成员 | LLM 提示词优化、大纲生成逻辑与结构化输出实现     |
| 左凌旭   | 成员 | RAG 检索流程实现、知识库构建与检索模块开发       |

## 二、成员个人双周进展

### 1. 潘越

- 完成了系统端到端 API 接口的详细设计，明确了 `PPTGenerator`类的核心方法定义与数据流向。
- 制定了首个双周集成演示的明确目标，即实现“输入主题，输出一个包含3页的简单结构化大纲”的完整流程闭环。
- 组织并主持了模块设计评审会议，对大纲生成 Prompt 方案和 RAG 流程设计进行了初步评审，统一了接口标准。
- 搭建了项目集成测试环境，并编写了首个端到端流程的测试脚本，为下周的初步集成做好准备。
- **本阶段工时：16 小时**。

### 2. 罗力

- 优化并最终确定了适用于商业、学术、教育三类场景的 PPT 大纲生成 Prompt，确保输出为严格的 JSON 结构，提高了格式稳定性。
- 实现了 `llm`模块的初步调用函数，能够接收主题并返回结构化的字典/列表。
- 扩展了模块功能，使其支持接收一份文本文档作为输入，可自动提取核心主题并生成对应大纲。
- 为生成逻辑添加了基础的自检提示，以初步校验大纲各部分之间的逻辑连贯性。
- **本阶段工时：18 小时**。

### 3. 左凌旭

- 确定了知识库文档的预处理流程，包括文本分割与清洗策略。
- 完成了向量数据库（采用 Chroma）的本地部署与接入，实现了文档的嵌入向量化与存储功能。
- 开发了基础检索功能，能够根据给定的查询文本（如PPT页面标题）返回最相关的若干个知识片段。
- 初步设计了检索结果的重排与过滤规则，为下一阶段的内容增强与事实性校验打下基础。
- **本阶段工时：18 小时**。

### 4. 上官思洋

- 设计了系统核心的 `EnhancedPPT`数据模型，明确了包含幻灯片列表、每页标题、要点、备注及引用来源等字段的结构。
- 完成了 PPT 导出库（`python-pptx`）的技术选型与初步调研。
- 基于选定的库，实现了将数据模型中的单页内容写入 `.pptx`文件的基础功能函数。
- 创建了简单的 PPT 模板文件，包括标题页、节标题页和内容页，为后续的自动化生成提供样式基础。
- **本阶段工时：16 小时**。

## 三、组长汇总

本双周是项目从“设计规划”进入“实质开发”的关键阶段。核心进展在于各模块完成了详细设计并输出了可运行的初步原型。大纲生成模块已具备结构化输出能力，RAG检索模块完成了知识库构建与基础检索，导出模块定义了数据模型并实现了单页导出功能，为系统集成创造了条件。

总体来看，各模块并行开发顺利，初步达成了周期目标。下一阶段的核心任务是进行模块间的初步集成与联调，验证“主题输入 -> 大纲生成 -> 内容检索 -> 页面导出”这一主流程的可行性。当前主要风险在于各模块接口在集成时可能出现的数据格式不一致问题，需在集成测试中重点关注。
