**提交日期**：2026-04-12  
**项目名称**：PPT-Genius（基于 LLM 与 RAG 的 PPT 大纲智能生成与内容深度补全系统）

| --- | --- | --- |

## 二、成员个人双周进展

### 1. 潘越

- 本阶段完成项目总体目标和技术路线梳理，明确系统需要覆盖“主题输入 - 大纲生成 - 知识增强 - PPT 导出”的完整流程。
- 组织组内讨论，初步确定任务边界，避免前期工作分散。
- 整理项目 README 的介绍结构，补充项目背景、目标、成功标准和后续开发方向。
- 开始形成双周汇报模板，便于后续持续记录成员进展。
- **本阶段工时：16 小时**。

### 2. 罗力

- 完成 PPT 大纲生成的 Prompt 草案设计，重点约束标题层级、页间逻辑和内容粒度。
- 初步整理适用于商业、科研、教学三类场景的通用大纲模板。
- 对“主题驱动”和“文档驱动”两种输入方式进行对比，明确二者的生成侧重点。
- 梳理输出格式，尝试将模型结果限制为更适合后续程序处理的结构化文本。
- **本阶段工时：15 小时**。

### 3. 左凌旭

- 调研 RAG 方案的基本流程，包括文档切分、向量化检索、召回结果重排和内容拼接。
- 初步整理外部知识来源，确定后续优先接入课程资料、公开论文摘要和案例材料。
- 讨论检索内容与 PPT 页内容之间的对应关系，为“增强内容可溯源”建立基础规则。
- 汇总当前可行的检索增强思路，等待后续与大纲生成模块联调。
- **本阶段工时：16 小时**。

### 4. 上官思洋

- 记录项目原型展示所需的页面与导出功能需求，明确后续优先实现“可看、可导出、可复用”。
- 配合整理实验记录方式，准备后续对生成质量、结构合理性和事实准确性的测试表格。
- 整理项目文档目录建议，便于后续代码、说明、测试和示例分层管理。
- 对提交材料的排版与展示效果进行初步规划，确保后续报告和说明更易阅读。
- **本阶段工时：14 小时**。

## 三、组长汇总

本双周内，项目已完成从“想法明确”到“任务拆分”的关键过渡。当前阶段的主要成果是明确了系统目标、核心流程和成员分工，并初步形成了 Prompt 设计、RAG 检索和结果导出三个开发方向。

总体来看，项目进展符合预期，但仍处于基础搭建阶段，后续需要尽快完成可运行的最小原型，以便验证大纲结构质量和内容增强效果。当前风险主要在于生成结构与检索内容之间的耦合设计，以及后续实验评价标准的统一。
