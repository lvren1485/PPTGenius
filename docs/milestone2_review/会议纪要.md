# 会议主题：PPT大纲智能生成与RAG结合系统汇报

会议摘要：本次汇报展示了基于Agent架构的PPT智能生成系统，完成了端到端原型开发，实现了多轮迭代优化与知识溯源，并针对生成成本、时间及风格定制进行了深入探讨。

## 一、项目进度与架构设计

针对项目从 Workflow 向 Agent 架构的演进，会议同步了当前的核心进度与技术选型：
1. 里程碑与进度管理
核心指标达成情况：项目累计完成 82 个工时（占比 26.3%），剩余 57 个工时计划于下周完成。目前已完成端到端原型开发及静态测试，但多领域测试与文档输出尚待完善。
关键目标对齐：确立了结构评分大于 8-10 分、知识可溯源、支持多领域测试及客户端导出的四大核心目标。目前结构评分采用内部流程统计，后续将补充外部评分机制。

2. 技术架构与选型
Agent 协调层引入：系统架构重构为展示层、服务层、协调层及技术层。协调层基于 LangGraph 实现多 Agent 协作，负责意图理解与任务分发。
后端技术栈选型：选用 Python FastAPI 配合 LangGraph/LangChain 框架，利用 BM25 算法进行检索，数据库采用 MySQL 以支持异步访问，AI 模型暂定 DeepSeek API。
PPT 导出方案：封装 Python-pptx 库，通过解析 JSON 配置文件（参考 ECharts Option 模式）实现从 LLM 输出到 PPT 文件的桥接。

## 二、核心功能实现与工作流

会议详细拆解了从知识库构建到 PPT 生成的全链路逻辑，重点阐述了 Agent 的协同机制：

1. RAG 与知识库管理
多源数据解析：支持 PDF、Word、PPT 等多种格式解析，大表格数据提取特征值（如最大/最小值）并截取前 100 行存储，避免 LLM 处理海量数据。
网络工具集成：集成 DuckDuckGo 搜索引擎，LLM 获取 URL 后进行内容抓取与清洗，并将网络文本纳入知识库索引，支持后续 RAG 查询。
知识库隔离机制：BM25 索引按用户隔离，支持用户对知识文件进行增删改查，并可选择关闭网络工具以防止信息污染。

2. 多轮迭代生成机制
Generator-Evaluator 循环：采用生成器（Generator）调用工具生成大纲，评估器（Evaluator）基于问卷（含结构完整性、视觉元素、长度等指标）进行评分。
质量阈值控制：设定 8 分阈值，若评分低于阈值，系统将评估结果反馈给生成器进行优化，最大迭代次数设为 3 次，以防止无限循环。
人机交互闭环：支持用户在前端查看大纲结构，提供反馈意见并要求 Agent 进行修改，形成“系统生成-用户反馈-系统优化”的第三层交互循环。

3. PPT 生成策略演进
单 Agent 架构胜出：对比了多 Agent（Chart/Text/Shape 分工）与单 Agent 架构，发现多 Agent 存在元素覆盖与协调问题，最终采用单 Agent 方案以保证布局协调性。
两阶段生成流程：第一阶段由 Agent 生成配色方案与字体方案；第二阶段利用模板文件（含装饰元素）并发生成所有 Slide 内容，以降低时间开销。

## 三、测试评估与性能瓶颈

通过实际测试数据，会议分析了系统的量化表现及存在的性能瓶颈：

1. 核心性能指标
生成质量与成本：在 14 次对话测试中，大纲平均评分为 8.19 分。单次 PPT 生成成本约 1.12 元，单次大纲生成成本约 0.13 元。
时间开销分析：单次大纲生成耗时约 6-7 分钟，PPT 生成耗时约 7-8 分钟。主要瓶颈在于 LLM 的思考时间以及指令重试（约 10% 概率 Retry）。

2. 可追溯性评估
溯源率计算逻辑：目前可追溯性评分为 57.8 分，计算方式是将 PPT 中的每句话投喂给 BM25 索引，取 Top-1 的 Chunk 进行匹配并计算平均得分。
目标差距说明：该评分与项目设定的 80% 溯源率目标存在差距，主要原因是当前计算逻辑较为粗糙，尚未设定明确的阈值判定标准。

## 四、代码规范评审

按照里程碑会议要求，本次会议对 PPTGenius 后端核心代码进行了规范性评审，覆盖 API、Agent、Infrastructure 三层共 10 个核心文件，评审维度为命名规范、代码风格、注释文档、类型标注、模块化五项，综合评分 **4.03 / 5**。

1. 命名规范 (4.5/5)
PEP 8 近完全合规。模块名 `snake_case`、类名 `PascalCase`、函数/变量 `snake_case`、常量 `UPPER_CASE`、私有成员 `_前缀`、布尔变量 `is_/has_` 均使用正确。仅少量缩写变量（如 `pres`→`presentation`）可进一步改善可读性。

2. 代码风格与格式 (4.0/5)
导入排序（标准库→第三方→本地）规范，缩进与空行统一。少数 SSE 内联字典超 120 字符，建议提取为命名函数。全局建议运行 `ruff format` 统一尾随逗号和行长度。

3. 注释与文档 (3.5/5)
模块文档覆盖率 90%，公有函数 72%，私有函数仅 33%。`agent/outline/graph.py` 含 ASCII 流程图，为最佳范例；`db/models.py` 缺少 ER 概览文档；`_create_presentation_node`、`_assembly_node` 等复杂函数缺少文档字符串。无 TODO/FIXME 遗留标记。

4. 代码结构与模块化 (4.0/5)
三层架构 API→Agent→Infrastructure 严格分离，零循环依赖。最大文件 `coordinator.py` 649 行，建议提取 SSE 辅助函数和数据内容构建器至独立模块。发现一个 **P0 级问题**：`coordinator.py` 中 `_rationale_store` 为模块级可变列表，非线程安全，需重构为 LangGraph state 传递。已废弃管线（`phase2_sub_agent/`、`phase2_freedom/`）标记清晰。

5. 改进清单
- **P0**：消除 `_rationale_store` 模块级可变状态
- **P1**：补充 3 处缺失的复杂函数文档字符串
- **P2**：日志消息统一为英文
- **P3**：运行 `ruff format` 全局格式化

## 五、评审问答环节

1. 关于生成质量与迭代机制的探讨
【提问人】张启政：评估 Agent 的评分标准是什么？演示的 PPT 经过了几轮迭代？
【回答人】左凌旭：评估标准基于预设的问卷（如 Layout 数量、页均字数等）。演示 PPT 通常经过 2 轮迭代，系统会记录每次的迭代次数。

2. 关于可追溯性评分的疑问
【提问人】胡宝怡：PPT 中显示可追溯性为 57.8 分，满分是 100 分吗？这与 80% 的溯源率目标如何对应？
【回答人】左凌旭：该分数是通过 BM25 索引匹配 Top-1 Chunk 计算的平均分，目前尚未设定明确的阈值来判定是否“可追溯”，因此与 80% 的目标存在差异。

3. 关于风格定制与生成效果的确认
【提问人】2351131-韦世贸：生成 PPT 时能否自定义风格？演示 PPT 是否设定了特定风格？
【回答人】左凌旭：支持自定义风格。演示 PPT 未强制设定风格，而是通过 Prompt 引导 Agent 根据领域（如科普、汇报）自动选择冷/暖/中性色调。
