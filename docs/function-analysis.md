PPT生成agent粗略规划

软件形式：python脚本，提供命令行接口与包调用入口，用户输入主题和相关信息后，将生成过程输出至标准输出并将PPT输出放到指定目录。
（如何区分cli调用与包调用，并保证对应的信息传递，比如cli调用可以重定向输出，包调用通过yield不断返回）


tool list
1. RAG知识库检索
2. PPT模板设计与选择 -->  预设4-5种模板（也由agent设计），如果用户需要更多模板，可以调用agent设计新的模板，并将设计好的模板加入到模板库中供后续使用
> 模板设计提供固定的模板类型：比如节标题、标题、尾标题，两栏式、三栏式等。
1. 调整某页PPT内容   -->  根据用户输入的需求，调整PPT的文本与图片内容，不涉及布局调整，如删除某些元素、修改元素的位置等
2. 调整某页PPT布局   -->  根据用户输入的需求，调整某页PPT的布局，如调整文本与图片的位置、调整元素的大小等
> 4和5是否需要区分？是否可以合并为一个工具，根据用户输入的需求，调整PPT的内容与布局？
1. 根据数据生成图表  -->  多种图表生成
2. 根据文本生成表格  -->  PPT不适合展示复杂表格，所以只提供单一的表格生成工具，根据文本描述生成简单的表格内容并插入PPT中
> 表格是否需要单独一个工具？是否可以合并到模板涉及的工具中（因为表格的PPT布局相对确定）
1. 根据文本生成图片  -->  调用DALL-E等图像生成模型，根据文本描述生成相关图片
> API调用开销可能过大，可以尝试提供常用元素预设库，用户可以选择预设元素进行插入，减少API调用次数和费用
1.  搜索引擎查询
2.  用户选择工具  -->  根据用户输入的需求，向用户询问接下来要干什么并给出选项
3.  PPT内容优化建议  -->  根据生成的PPT内容，给出优化建议，如增加某些内容、调整结构等

agent划分（是否必要？）：
1. 规划agent：负责整体规划PPT的结构和内容，确定需要调用哪些工具来完成任务。
2. 大纲生成agent：根据用户输入的主题和相关信息，检索RAG知识库与搜索引擎，生成PPT内容。
3. PPT模板设计agent：根据大纲内容和用户偏好，设计PPT的布局和视觉风格。
4. PPT生成agent：根据大纲生成agent提供的PPT内容与PPT模板设计agent提供的模板设计，生成最终的PPT文件。
5. 图表生成agent：根据大纲内容生成agent提供的内容，生成相关的图表。

量化评估方案：
1. PPT逻辑评分：给三个不同模型的LLM一份问卷以及PPT大纲内容，要求其按照问卷评分，并给出理由。问卷内容包括：PPT内容的完整性、逻辑性、清晰度、视觉效果等方面。
2. 知识溯源：使用RAG知识库检索工具，评估生成的PPT内容是否能与RAG数据库中的相关知识点匹配。
3. 多领域适配测试：选择不同领域的主题（如科技、医疗、教育等），让模型生成对应领域的PPT，并评估其内容的专业性和准确性。

经济评估：
1. 开发成本：主要为开发人员的开发时长
2. 运行成本：主要为调用LLM和相关工具的API费用，使用代理工具拦截调用，统计调用次数和费用。
